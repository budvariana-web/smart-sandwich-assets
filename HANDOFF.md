## 2. Что решает проект

Кафе продаёт сэндвичи, бургеры и работает с доставкой. Первый реализованный цифровой контур — **экранное меню** для горизонтального дисплея около **47″ / 1920×1080**.

Задача экрана:

- сотрудник меняет состав, цены, доступность, порядок и фото в Google Таблице;
- посетительский экран автоматически получает изменения;
- телевизору не нужен Google-аккаунт;
- исходная таблица не становится публичной.

## 4. Источник данных: Google Sheet

Таблица создавалась как **Smart Sandwich Bar Test Menu**. Источником истины является лист `MENU`; `SETTINGS` — опциональный лист конфигурации.

### Лист `MENU`

Первая строка — заголовки. Минимально обязательны только `Название` и `Цена`.

| Колонка | Назначение |
|---|---|
| `Категория` | Раздел меню; пустое значение становится `Другое`. |
| `Название` | Наименование позиции. |
| `Описание` | Состав/короткое описание. |
| `Цена` | Текущая цена. |
| `Старая цена` | Перечёркнутая цена для акции. |
| `В наличии` | `Нет`, `false`, `0`, `нет в наличии`, `off` скрывают позицию; пусто = доступна. |
| `Порядок` | Числовая сортировка внутри категории. |
| `Фото` | `https://…` либо встроенный asset-ID. |
| `Бейдж` | Например `Хит`, `−10%`. |

Поддерживаются русские и английские варианты заголовков. Сортировка: категория → `Порядок` → номер строки.

### Лист `SETTINGS`

| Параметр | Типовое значение | Значение |
|---|---:|---|
| `Бренд` | `SMART SANDWICH BAR` | Заголовок экрана. |
| `Обновление сек` | `60` | Период нового чтения таблицы. Ограничение в коде: 20–600 сек. |
| `Перелистывание сек` | `15` | Пауза между страницами. Ограничение: 8–90 сек. |

## 5. Поведение интерфейса

- Сетка: 4 колонки на широком экране; 3 колонки при ширине менее 1000 px.
- Без изображений: до 12 карточек на страницу.
- Если есть хотя бы одна позиция с изображением: до 8 карточек на страницу.
- При нескольких страницах экран сам листается.
- Последняя успешно загруженная версия хранится в `localStorage`; при недоступности сети показывается она же с заметкой о потере связи.
- Текст из Sheet HTML-экранируется: инъекции из названий/описаний не должны исполняться как HTML.

### Валюта — важное правило

Backend оставляет цену как есть, если значение уже содержит `€`, `₽` или `$`; обычному числу без символа он исторически добавляет `₽`.

**Практическое правило сейчас:** для евро в Sheet хранить явный символ, например `€5,45` или `5,45 €`. Не заносить только `5.45`, пока не изменён `formatPrice_()` в `Code.gs` и не пройдена проверка.

В прошлой работе цены тестового меню были конвертированы в евро ориентировочно по курсу `€1 = 89,8998 ₽` с округлением до €0,01. Это была техническая конвертация на дату работы, а не источник текущего коммерческого курса; реальные цены подтверждает владелец.

## 6. Изображения и кэш ТВ

### Текущая реализация

В `Assets.html` встроены стабильные изображения как data-URL. Поддерживаемые asset-ID:

- `asset:tuna-avocado`;
- `asset:tuna-salad-300`.

В `Code.gs` эти ID разрешены `safeImageUrl_()`, а `Index.html` разворачивает их через `window.SMART_SANDWICH_ASSETS`.

Плюс такого подхода: карточка не зависит от внешнего фотохостинга, случайной смены URL или отдельной авторизации к изображению.

### Исторический симптом и защита

На ТВ фото однажды не отобразилось до ручного reload, затем появилось. Вероятные причины: старый кэш кода страницы, Android Chrome/WebView, задержка загрузки фото либо 60-секундный refresh.

Добавлена защита от устаревшего build:

- `BUILD_ID = menu-20260718-5` есть и в `Code.gs`, и в `Index.html`;
- backend отдаёт `buildId` вместе с данными меню;
- если экран получил данные от другого build, он делает **однократный** reload с параметром `?build=…`;
- номер build запоминается в `sessionStorage`, поэтому не возникает бесконечный reload-цикл.

**При изменении `Code.gs`, `Index.html` или `Assets.html`:** меняйте `BUILD_ID` синхронно в обеих точках, публикуйте новую версию, затем проверяйте экран.

### Если фото снова нет на ТВ

1. Сначала получить фото именно из браузера ТВ/Fully Kiosk с видимым URL/ошибкой, а не скриншот домашнего экрана Android.
2. Проверить, что новая версия сайта действительно подтянулась: reload один раз или открыть URL с `?build=<текущий-build>`.
3. Проверить сеть ТВ и обновления Chrome / Android System WebView.
4. Не менять сразу код и источники изображений одновременно — сначала локализовать: кэш, сеть, asset или rendering.
5. Для постоянного режима предпочтителен **Fully Kiosk Browser**: fullscreen, автозапуск URL, восстановление после питания и отключённая заставка.

## 8. Безопасная процедура изменения меню

### A. Изменить контент, цену, доступность, порядок или URL-фото

1. Владелец/уполномоченный сотрудник правит нужную строку `MENU`.
2. Убеждается, что в цене есть нужный символ валюты.
3. Ждёт до 60 секунд; при нескольких страницах даёт экрану пройти полный цикл.
4. Проверяет на реальном экране: название, цена, наличие, карточка/фото, читаемость.

Код и новый deployment для этого пути не нужны.

### B. Изменить логику, вёрстку или встроенные assets

1. Изменить локальные файлы `Code.gs`, `Index.html`, `Assets.html` и при необходимости manifest.
2. Если менялся фронтенд или asset, синхронно повысить `BUILD_ID` в `Code.gs` и `Index.html`.
3. Запустить:

```bash
cd /home/dmitrii/smart-sandwich-menu-display
node tests/render-test.js
python3 -m json.tool appsscript.json >/dev/null
```

4. Использовать существующую локальную OAuth-сессию владельца и запустить обновление deployment. **Токен/клиент/служебный JSON не показывать, не отправлять и не коммитить.**
5. Проверить публичный `/exec` анонимным HTTP-запросом и визуально на 1920×1080.
6. Один раз обновить страницу на ТВ, чтобы она получила build guard; далее будущие code/asset обновления должны подхватываться автоматически.

## 9. Проверка после изменений

Минимальный checklist:

- [ ] `/exec` возвращает `HTTP 200`.
- [ ] Нет offline/error UI на чистом браузере.
- [ ] Цены отображаются с ожидаемой валютой, старая цена перечёркнута.
- [ ] Строки `В наличии = Нет` исчезли.
- [ ] Не более 8 карточек с фото или 12 текстовых карточек на страницу.
- [ ] Перелистывание соответствует `SETTINGS`.
- [ ] Длинное название/описание не ломает карточку.
- [ ] Изображение видно на реальном ТВ, не только desktop Chromium.
- [ ] После code/assets update build guard не создаёт цикл перезагрузок.

## 10. Доступы: как передавать безопасно

Новому агенту **не нужны** секреты для чтения этого документа или просмотра публичного экрана.

Если ему потребуется работа с таблицей/деплоем:

1. Владелец добавляет нужный Google-аккаунт как редактора именно к таблице, с минимальным уровнем доступа.
2. Для административной интеграции владелец создаёт/выдаёт новый отдельный доступ через защищённый канал и хранит его вне чата.
3. OAuth проходит на локальном устройстве владельца; результат не пересылается в Telegram.
4. Перед удалёнными изменениями новый агент сначала делает read-only проверку, затем предоставляет владельцу понятный план изменения и результат проверки.

Нельзя передавать в группу: OAuth-коды/refresh tokens, API keys, service-account JSON, cookie, приватные локальные пути к credential cache, аккаунтные пароли.

## 11. История решений

1. Выбрана бессерверная схема Google Sheet → bound Apps Script → public `/exec` вместо публичной таблицы.
2. Публичный `/exec` в начале возвращал `403`, потому что владельцу требовалась первичная runtime-авторизация `SpreadsheetApp`; после исполнения `getMenu` владельцем endpoint заработал анонимно.
3. Публичный доступ нужен только экрану; редактирование остаётся ограниченным таблицей.
4. Для ТВ важнее kiosk browser и защита от кэша, чем вход в Google.
5. Для проблемных фото выбрана стратегия небольших встроенных JPEG assets; это устраняет зависимость от внешнего хостинга.
6. Цены переводились в евро; при дальнейшей работе нельзя полагаться на старый обменный курс — подтверждать реальные цены у владельца.

## 12. Что пока не сделано / следующие полезные задачи

1. **Заменить тестовый каталог реальным.** Подтвердить финальные названия, граммовки, цены, availability, акционные цены, фото и порядок.
2. **Проверить все позиции на реальном TV.** Особенно после длительной работы/сна/перезагрузки питания.
3. **Явно унифицировать валюту.** Если евро — изменить default в `formatPrice_()` на `€` и хранить цены в едином формате, после согласования владельцем.
4. **Подготовить операционный режим устройства.** Fully Kiosk/Chrome kiosk, автозапуск, отключение screensaver, доступная сеть и простой способ ручного reload.
5. **Следующие контуры автоматизации кафе.** Заказы и доставка, стоп-лист, остатки, закупки, промо, аналитика и CRM — это отдельные проекты; в текущем репозитории они ещё не реализованы.

## 13. Правила для нового бота в этом групповом чате

- Не инициировать автономный диалог с другим ботом и не создавать bot-to-bot loop.
- Отвечать только на человеческий запрос; не отвечать на служебные сообщения, tool/runtime notices, прерывания и статусы.
- Не публиковать секреты и не просить прислать их в чат.
- Перед изменением live-меню сначала сформулировать понятную цель, scope, rollback и проверку; после изменения сообщать фактический результат.
- Операционный формат: сначала 🟢/🟡/🔴 решение, затем краткий блокер и следующий шаг.
