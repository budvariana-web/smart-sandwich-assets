## 0. ЗОЛОТЫЕ ПРАВИЛА (читать первыми)

1. **ПЕРЕД любой правкой Index.html/Code.gs — `git log --oneline -8` и `git status`**.
   Файлы мог менять НЕ только пользователь — их мог менять сам агент в прошлой сессии
   (реальный случай: шрифты Glock встроил агент в v59, а в новой сессии это
   интерпретировалось как «внешняя правка пользователя»).
2. **НЕ полагаться на память/компакт о текущем состоянии кода — читать с диска.**
   Единственный источник правды — файлы + git.
3. **После каждого деплоя — `python verify_menu.py`** (прогрев прокси + сверка BUILD_ID).
4. **Скриншот для пользователя — всегда проверять `ls` перед отправкой** (`MEDIA:/abs/path`).
5. **Перед объявлением «готово» — проверить результат в браузере** (Playwright/DevTools),
   не только curl+grep по исходнику.
6. **Пути к файлам проекта — только абсолютные** (`C:/Users/Asus/AppData/Local/hermes/projects/smart-sandwich-bar/...`).
   `search_files` НЕ видит большие файлы (Index.html 228KB) — использовать read_file/patch/grep.

## 2. GAS-прокси кэш (дважды ловили: v52, v55)

**Симптом:** после `deploy.py` первый запрос Playwright возвращает СТАРЫЙ HTML (старая тема,
старые шрифты), хотя `curl` уже видит новый. Это НЕ браузерный кэш — это серверный кэш
прокси script.google.com / googleusercontent.com.

**Решение (уже внедрено, v58+):**
- `deploy.py` вшивает уникальный `BUILD_ID` (`b260802-175907`) в Code.gs и Index.html
  (плейсхолдер `%%BUILD_ID%%`), пишет в `last-build.txt`.
- `verify_menu.py` греет прокси curl'ом (`/exec?warm=<ts>`), сверяет `window.BUILD_ID`
  в iframe, reload до 4 раз, ждёт карточки, снимает метрики, делает скриншот.
- Цикл: `python deploy.py "описание"` → `python verify_menu.py`.

**⚠️ Ловушка:** не добавлять `set_extra_http_headers({"Pragma":"no-cache"})` — это
non-safelisted CORS-заголовок → preflight → GAS блокирует `?page=data` (консоль: CORS error).

**⚠️ Ловушка:** плейсхолдер `%%BUILD_ID%%` может быть затёрт (вручную или прошлой сессией)
на литерал `'menu-20260802-glock'`. Диагностика: `grep -n "BUILD_ID" Code.gs Index.html`.
Если warm-up стабильно stale — проверять исходники, не «греть прокси сильнее».

## 6. Погода Бара — только открытые данные (v87)

- Температура в виджете означает **погоду города Бар, Черногория**, а не температуру внутри помещения. `Code.gs` больше не читает и API больше не отдаёт `indoorTemperature`; поле `Температура в баре` в `SETTINGS` не нужно.
- Клиент запрашивает Open-Meteo без ключа (42.0938, 19.1002): current `temperature_2m`, `apparent_temperature`, `precipitation`, `weather_code`, `wind_speed_10m` и дневные min/max. Обновление — раз в 10 минут.
- Weather-card — **пассивный** дополнительный слайд верхней promo-карточки: город → крупная температура+иконка → «ясно · min—max» → ощущается/ветер/дождь. Нет кнопок, ручных настроек и фальшивых данных.
- Последний успешный ответ сохраняется в localStorage до 6 ч. При кратком сетевом сбое он остаётся на экране; при первом сбое показывается нейтральное сообщение. `scheduleWeather()` запускается один раз и не перезапускается при меню-refresh (60 с).
- Проверка: `python verify_weather_widget.py` — Chromium 1280×720, живой Open-Meteo, погодный слайд принудительно включён; ожидаются card внутри `#ann-top`, 0 console errors. В v87 card 133px в блоке 181px.

## 7. Многоязычные карточки и видео-страницы (v90+)

- Единственный runtime-источник — лист **`MENU`**. Колонки A–K сохранены; L–T содержат локализации:
  `Категория (ME) | Название (ME) | Описание (ME) | Категория (EN) | Название (EN) | Описание (EN) | Категория (DE) | Название (DE) | Описание (DE)`.
  Лист `MENU_ME` был резервом только на время миграции и не должен читаться `Code.gs`.
- API каждого товара возвращает `languages.{ru,me,en,de}` с `category/name/description`; цена, фото, badge, visibility и порядок общие. API также читает из `SETTINGS`:
  - `Показывать категории` — настоящий checkbox (`BOOLEAN`): `false` скрывает категорию целиком;
  - `Наборов до видео` — целое число `>= 1`, default `3`.
- **Один набор** = до трёх товаров на двух карточных экранах: сначала `ME+RU`, затем те же позиции `EN+DE`. После каждых N наборов добавляется fullscreen-видео. Финальная неполная пачка перед возвратом к первому товару также завершается видео.
  Для 23 позиций и N=3: 8 наборов → 16 экранов карточек → видео после наборов 3, 6 и 8 (страницы 7, 14, 19 при счёте от 1).
- В `buildBilingualPages()` fullscreen-клипы вставляются только после двух языковых страниц набора. Не добавлять хвост `while` с роликами и не допускать `video → video`. `fullscreenVideoBatch` выдаёт ограниченный slot count пакет без повторов и сдвигает курсор только по завершении полного menu cycle.
- Blob-политика v79.1 остаётся обязательной: ровно один следующий ролик `fetch → Blob`, прежний Blob освобождается, для Blob-пути переход только по `ended`; fallback timer — лишь для failure прямого сетевого пути.
- **Нулевая терпимость к text clipping — release gate:** любая правка TV menu должна запускать audit **до commit/deploy и повторно на публичном GH Pages URL**. Аудит обязан пройти все 19 pages, обе языковые пары и минимум `1280×720`, `1920×1080`, `3840×2160`; при любом нарушении возвращать non-zero и запрещать публикацию. Для каждого logical source field (`category/name/description/price/oldPrice/badge`, promo/weather/countdown/header) проверять: (1) source text не исчез из rendered text намеренно или через CSS; (2) нет `line-clamp`, `text-overflow`, `display:none` у требуемого текста; (3) `scrollHeight ≤ clientHeight + 1` и `scrollWidth ≤ clientWidth + 1`; (4) его paint bounds полностью лежат **внутри визуальной панели карточки/announcement/weather**, а не просто выходят наружу при `overflow:visible`; (5) glyph pixel bounds имеют ≥1 px сверху/снизу. Обязательное доказательство — contact sheet или скриншоты **всех 16 menu‑страниц**, а не один удачный кадр. Нельзя считать line-clamp, скрытую строку, overflow-visible или отсутствие DOM scroll допустимым компромиссом. **Доставка evidence в Telegram:** 19 исходных full-resolution PNG отправлять отдельными document‑файлами через `[[as_document]] MEDIA:/absolute/path/screenshot.png` (не media/photo, не ZIP, не переименование расширения); запрещены ресайз, коллаж, плашки поверх UI и любые изменения pixels screenshot. JSON audit отправлять отдельным document‑файлом тем же штатным marker.

## 8. Видео/сеть: сохранённые ограничения

- Правая панель (`#video-slot`) — отдельный механизм (`preload='metadata'`, `loop=false`, `ended` → `nextVideo()`). Не переводить ролики на `preload=auto`: это параллельно скачивает все MP4 и ломает слабый Wi‑Fi ТВ.
- MP4 должны быть faststart; GitHub Pages даёт требуемый `video/mp4` + CORS. `raw.githubusercontent` для видео не использовать.
- `schedulePages()` не должен сбрасывать идущий таймер при refresh, а видео стартует только при входе на его страницу, не на повторном `applyMenu()`.

**Структура MENU (актуально):**
`A Категория (RU) | B Название (RU) | C Описание i-food (RU) | D Цена | E Старая цена | F В наличии | G Порядок | H Фото | I Бейдж | J Описание наше (RU) | K Показывать | L–N Категория/Название/Описание (ME) | O–Q Категория/Название/Описание (EN) | R–T Категория/Название/Описание (DE)`

- **C** — owned синком (пишется из API i-food, `menu_lang_texts`).
- **J** — ручное «наше»; синк его НЕ затирает. Приоритет: J > C > legacy «Описание».
- **K** — чекбокс: FALSE скрывает товар с экрана (Code.gs `continue`), пусто/TRUE = показывать. ⚠️ При чтении НЕЛЬЗЯ делать `obj['показывать'] || ''`: булево `false` — falsy и превращается в пустую строку, из-за чего выключенный товар возвращается в API/ротацию. Использовать `Object.prototype.hasOwnProperty.call(obj, 'показывать')` и присваивать значение напрямую. Синк сохраняет K по имени товара, новые строки = TRUE.

**⚠️ Ловушка (Sheets API):** структурные операции — `POST spreadsheets/{id}:batchUpdate` (двоеточие!). Слэш-форма `/batchUpdate` возвращает HTML-страницу «не можем открыть файл» (400). Значения — `values:batchUpdate`.
