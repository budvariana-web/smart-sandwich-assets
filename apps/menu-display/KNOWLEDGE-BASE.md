## 0. ЗОЛОТЫЕ ПРАВИЛА (читать первыми)

1. **ПЕРЕД любой правкой Index.html/Code.gs — `git log --oneline -8` и `git status`**.
   Файлы мог менять НЕ только пользователь — их мог менять сам агент в прошлой сессии
   (реальный случай: шрифты Glock встроил агент в v59, а в новой сессии это
   интерпретировалось как «внешняя правка пользователя»).
2. **НЕ полагаться на память/компакт о текущем состоянии кода — читать с диска.**
   Единственный источник правды — файлы + git.
3. **После каждого деплоя — `python verify_menu.py`** (прогрев прокси + сверка BUILD_ID).
4. **Скриншот для пользователя — всегда проверять `ls` перед отправкой** (`MEDIA:/abs/path`).
5. **Перед объявлением «готово» — проверить результат в браузере** (Playwright/DevTools),
   не только curl+grep по исходнику.
6. **Пути к файлам проекта — только абсолютные** (`C:/Users/Asus/AppData/Local/hermes/projects/smart-sandwich-bar/...`).
   `search_files` НЕ видит большие файлы (Index.html 228KB) — использовать read_file/patch/grep.

## 2. GAS-прокси кэш (дважды ловили: v52, v55)

**Симптом:** после `deploy.py` первый запрос Playwright возвращает СТАРЫЙ HTML (старая тема,
старые шрифты), хотя `curl` уже видит новый. Это НЕ браузерный кэш — это серверный кэш
прокси script.google.com / googleusercontent.com.

**Решение (уже внедрено, v58+):**
- `deploy.py` вшивает уникальный `BUILD_ID` (`b260802-175907`) в Code.gs и Index.html
  (плейсхолдер `%%BUILD_ID%%`), пишет в `last-build.txt`.
- `verify_menu.py` греет прокси curl'ом (`/exec?warm=<ts>`), сверяет `window.BUILD_ID`
  в iframe, reload до 4 раз, ждёт карточки, снимает метрики, делает скриншот.
- Цикл: `python deploy.py "описание"` → `python verify_menu.py`.

**⚠️ Ловушка:** не добавлять `set_extra_http_headers({"Pragma":"no-cache"})` — это
non-safelisted CORS-заголовок → preflight → GAS блокирует `?page=data` (консоль: CORS error).

**⚠️ Ловушка:** плейсхолдер `%%BUILD_ID%%` может быть затёрт (вручную или прошлой сессией)
на литерал `'menu-20260802-glock'`. Диагностика: `grep -n "BUILD_ID" Code.gs Index.html`.
Если warm-up стабильно stale — проверять исходники, не «греть прокси сильнее».

## 6. Погода Бара — только открытые данные (v87)

- Температура в виджете означает **погоду города Бар, Черногория**, а не температуру внутри помещения. `Code.gs` больше не читает и API больше не отдаёт `indoorTemperature`; поле `Температура в баре` в `SETTINGS` не нужно.
- Клиент запрашивает Open-Meteo без ключа (42.0938, 19.1002): current `temperature_2m`, `apparent_temperature`, `precipitation`, `weather_code`, `wind_speed_10m` и дневные min/max. Обновление — раз в 10 минут.
- Weather-card — **пассивный** дополнительный слайд верхней promo-карточки: город → крупная температура+иконка → «ясно · min—max» → ощущается/ветер/дождь. Нет кнопок, ручных настроек и фальшивых данных.
- Последний успешный ответ сохраняется в localStorage до 6 ч. При кратком сетевом сбое он остаётся на экране; при первом сбое показывается нейтральное сообщение. `scheduleWeather()` запускается один раз и не перезапускается при меню-refresh (60 с).
- Проверка: `python verify_weather_widget.py` — Chromium 1280×720, живой Open-Meteo, погодный слайд принудительно включён; ожидаются card внутри `#ann-top`, 0 console errors. В v87 card 133px в блоке 181px.

## 7. Видео-страницы (v71–v89)

- **Полноэкранные видео** вставляются ТОЛЬКО в `both`-режиме после каждой пары
  RU+ME (`interleaveVideoPages`, после нечётных индексов). В одном меню-цикле
  доступно только `floor(страницы_меню / 2)` таких слотов: сейчас 46 позиций =
  16 страниц меню = 8 fullscreen-слотов. **v89:** при 17 роликах они идут пакетами
  `8 → 8 → 1` в последовательных меню-циклах, а не в хвосте одной страницы цикла;
  счётчик первого цикла — **24** (16 меню + 8 видео).
- **v72 (f95e12a):** длительность видео = РЕАЛЬНАЯ длина ролика, а не хардкод:
  - у полноэкранного `<video>` убран `loop` → событие `ended` → `advancePage()`.
  - `pageDurationSec()` возвращает `video.duration` (фолбэк `videoSeconds`=40 пока
    метаданные не загрузились); `loadedmetadata`/`durationchange` → `rearmIfVideoPage()`.
  - `advancePage()` с дебаунсом 1.5с (защита от двойного срабатывания таймер+ended).
  - **Рефреш не сбрасывает позицию**: `applyMenu()` сохраняет `prevPage`
    (`Math.min(prevPage, pages.length-1)`), раньше каждый рефреш (refreshSeconds=60)
    прыгал на страницу 1 — пользователь видел «после видео опять первая страница».
  - ролики в SETTINGS короткие (~10с), а было videoSeconds=40 → крутило 4 повтора.
- **v89 (регрессия после добавления 17 роликов):**
  1. `interleaveVideoPages` вставляет ролики только после RU+ME-пары и **никогда**
     не имеет `while`-хвоста; соседние fullscreen-страницы запрещены.
  2. Стабильный shuffled-порядок выдаётся пакетами `fullscreenVideoBatch`; курсор
     сдвигается только в конце меню-цикла, поэтому каждый URL показывается один раз
     до повтора, а 60-секундный refresh не перезапускает пакет.
  3. Для Blob-клипа событие `ended` — основной триггер перехода; `duration + 15с`
     остаётся только аварийным fallback для прямого сетевого воспроизведения.
  4. `schedulePages()` не сбрасывает идущий таймер при refresh, а ролик стартует
     только при входе на видео-страницу, не при повторном `applyMenu`.
- Правая панель (`#video-slot`, 1/4 экрана) — отдельный механизм (`ensureVideoElements`,
  `loop=false`, `ended` → `nextVideo()`, переключение ~каждые 10с по длине клипа).
- **v77 (27d6953):** ролики → GH Pages `budvariana-web.github.io/smart-sandwich-assets/assets/videos/`
  (video/mp4+CORS, вместо raw.githubusercontent octet-stream+nosniff); `preload='metadata'` на обоих
  `<video>` (защита ТВ от параллельной загрузки ~30МБ). ⚠️ **MP4 ОБЯЗАТЕЛЬНО faststart** (moov в
  начало, `ffmpeg -c copy -movflags +faststart -f mp4`): Firefox/WebKit при moov в конце +
  preload=metadata виснут на readyState=0 (не играют ни мини-блок, ни полноэкранно), Chromium
  доискивается сам. Пересобрано все 9 роликов (a53cc87). CDN Pages кэширует ~10 мин.
- **v78 (4400233, 04.08):** серый треугольник полноэкранного видео — применён приём мини-блока:
  `.fullscreen-video video { opacity:0; transition: opacity .25s }` + `.video.ready { opacity:1 }`,
  класс `ready` вешается по событию `playing` (первый кадр отрисован). `preload='metadata'`
  НЕ возвращать на `auto` (v77 сознательно; повторный вход на ту же видео-страницу при том же
  dataset.src = 0 сетевых запросов, буфер элемента сохраняется).
- **v79.1 (5590a7c / 04.08):** browser Range-кэш и hidden `<video preload=auto>` не гарантируют
  полный буфер на слабой сети — воспроизведено: при 1 Мбит/с старый поток прошёл лишь 3.67с/10с
  до прежней страховки. Теперь `preloadNextFullscreenVideo()` делает ровно ОДИН `fetch(url)` →
  полный `Blob`/`blob:` URL будущего ролика; пока Blob не готов, видео-страница ждёт, а после
  готовности играет из RAM и переходит ТОЛЬКО по `ended` (без duration+15 таймера). Blob старого
  ролика освобождается перед следующим, память ограничена одним файлом. Все 9 файлов пережаты
  для слабой сети: 8 горизонтальных 960×540/~0.55–0.66 Мбит/с, длинный вертикальный 360×640/
  0.22 Мбит/с (997КБ). `python throttled_video_probe.py 1000 45 30 <имя>` подтвердил blobSource,
  полный буфер [0,duration] и ended: 10.0с / 35.96с.
- Проверено: ролик 10.0с → видео-страница держалась 10.2с → «4 / 26»; страница меню ровно
  15.2с даже при рефреше в середине показа (монитор); E2E — PASS «advanced via ended».
- Инструменты (корень проекта): `python menu_monitor.py <сек>` — живые переходы страниц;
  `python video_probe.py` — состояние ролика на видео-странице; `python make_static.py` —
  пересборка статической копии GH Pages из Index.html (после деплоя ОБЯЗАТЕЛЬНО).

**Структура MENU (актуально):**
`A Категория | B Название | C Описание i-food | D Цена | E Старая цена | F В наличии | G Порядок | H Фото | I Бейдж | J Описание наше | K Показывать`

- **C** — owned синком (пишется из API i-food, `menu_lang_texts`).
- **J** — ручное «наше»; синк его НЕ затирает. Приоритет: J > C > legacy «Описание».
- **K** — чекбокс: FALSE скрывает товар с экрана (Code.gs `continue`), пусто/TRUE = показывать. ⚠️ При чтении НЕЛЬЗЯ делать `obj['показывать'] || ''`: булево `false` — falsy и превращается в пустую строку, из-за чего выключенный товар возвращается в API/ротацию. Использовать `Object.prototype.hasOwnProperty.call(obj, 'показывать')` и присваивать значение напрямую. Синк сохраняет K по имени товара, новые строки = TRUE.

**⚠️ Ловушка (Sheets API):** структурные операции — `POST spreadsheets/{id}:batchUpdate` (двоеточие!). Слэш-форма `/batchUpdate` возвращает HTML-страницу «не можем открыть файл» (400). Значения — `values:batchUpdate`.
